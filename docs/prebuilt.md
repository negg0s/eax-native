# Готовые бинарные shim'ы (prebuilt/)

В репозитории лежат два собранных Windows PE файлов `dsound.dll`. Они используются
`eaxctl install` как источник по умолчанию, чтобы не требовать MinGW на машине
пользователя.

| Файл | Архитектура | Размер | SHA-256 |
|---|---|---|---|
| `prebuilt/pe32/dsound.dll` | i386 (для `syswow64`) | 129385 B | `1295dac4c6745d212779764fbd984279f4251ab310c1cc561c4a8c4968174671` |
| `prebuilt/pe64/dsound.dll` | x64 (для `system32`) | 131195 B | `0490c0f50e857b3d9e982b58c2a7d72e441fd4944ecdcfe506acfe8469019f4e` |

Откуда они: кросс-компиляция `wine-integration/dsound_shim.cpp` через
MinGW (`ci/build_windows_pe.sh`), целевой компилятор x86_64-w64-mingw32-gcc /
i686-w64-mingw32-gcc. Бинарник небольшой: это пас-форвардер COM-интерфейсов,
который оборачивает вызовы и отправляет EAX property sets в нативную часть.

Проверить у себя:

```
sha256sum prebuilt/pe64/dsound.dll prebuilt/pe32/dsound.dll
```

К архитектуре не придраться и по `objdump`: 64-битный файл собирается один раз,
его магия PE с `machine 0x8664`, 32-битный с `0x014C`. `eaxctl status` проверяет
это поле автоматически.

release notes, а из дерева репозитория убрать (весит немного, но релизы чище).
Решение за автором.
